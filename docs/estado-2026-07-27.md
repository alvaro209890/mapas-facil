## Atualização automática (a partir da 0.5.2)

O app avisa quando sai versão nova e atualiza com um clique — ver
[F1-11 §P2](../Fase_1_Desktop/planos/11-empacotamento-instalador.md#p2--auto-update)
para o desenho.

- verifica no boot e a cada 4 h;
- **nada baixa nem instala sozinho**: "Atualizar agora" baixa,
  "Reiniciar e instalar" aplica;
- o aviso some quando não há o que fazer, em vez de ficar fixo no topo;
- falha de rede vira aviso discreto — o app continua funcionando.

**Quem está na 0.5.0/0.5.1 instala a 0.5.2 na mão, uma vez** — aquelas versões
foram empacotadas sem o atualizador.

### Duas coisas que passaram a ser obrigatórias em toda release

1. **Tag `vX.Y.Z`.** O provider GitHub do `electron-updater` lê a tag da última
   release e extrai a versão dela; `desktop-vX.Y.Z` não é semver e quebraria a
   verificação. Por isso a `0.5.2` saiu como `v0.5.2`.
2. **Subir `latest.yml` e o `.blockmap` junto do `.exe`.** Sem o `latest.yml` o
   app simplesmente não enxerga a atualização.

O comando que faz as duas coisas:

```bash
cd Fase_1_Desktop/app && pnpm dist
cd release && gh release create vX.Y.Z \
  MapasFacil-Setup-X.Y.Z.exe MapasFacil-Setup-X.Y.Z.exe.blockmap \
  latest.yml download-manifest.json sha256.txt
```

## Os três bugs que bloqueavam o piloto

### 1. O app instalado não abria

**Causa raiz:** a 0.5.0 empacotou o sidecar como `resources/nucleo/nucleo.exe`,
mas [`localizar.ts`](../Fase_1_Desktop/app/electron/nucleo/localizar.ts)
procurava só `mapasfacil-nucleo.exe`. O spawn falhava calado, o núcleo nunca
subia e a janela ficava presa em "núcleo iniciando" — parecia um app aberto e
morto.

O binário empacotado estava íntegro: testado direto no stdio, respondia NDJSON
normalmente. Era só o nome. A busca agora aceita os dois.

### 2. Login pedido duas vezes

Eram **dois** defeitos somados:

- o main empurrava o estado da ponte em `did-finish-load`, que acontece **antes**
  de o React assinar no `useEffect`. O push se perdia e a tela ficava em
  "iniciando" para sempre; como a guarda de login só roda com o núcleo `pronto`,
  o login nunca aparecia. Agora existe o canal de *pull* `nucleo:estado-atual`,
  e um push que chegue antes da resposta vence (é mais novo).
- `App.tsx` renderizava o shell enquanto o núcleo subia — o app "abria" sem
  sessão e chutava o usuário para o login depois. O shell agora só monta com
  sessão confirmada.

Fluxo verificado no app rodando: **cadastro → direto no workspace**.

### 3. WMS/WMTS exigindo configuração manual

**Causa raiz:** `resolver.py._obter_authkey` lê a chave **só do cofre** e lança
`NU-102` ("configure em Preferências") quando falta — e **30 das 41 camadas** do
catálogo exigem `sema_authkey`. Mas `sincronizar_chave_projeto_no_cofre()`
gravava apenas a `deepseek_api_key`.

Agora as três chaves (DeepSeek, SEMA, Planet) são provisionadas no login.
Verificado com conta nova: as três aparecem no Credential Manager e a camada
`car_sema` resolve sozinha.

**Risco aceito** (decisão sua, 2026-07-27): embutir SEMA/Planet no instalador
significa que qualquer usuário consegue extraí-las do `.exe`. Detalhe e
alternativa (proxy no Acer) em
[`provisao-deepseek-instalador.md`](provisao-deepseek-instalador.md).

   existe a tool `definir_basemap`, mas nada que ofereça o catálogo de forma
   navegável no chat.

## Armadilha do download no site (resolvida em 2026-07-27)

O site continuou anunciando a 0.5.0 mesmo depois da release nova, por **duas**
camadas de env com precedência sobre o manifesto (`lib/download.ts` lê
`NEXT_PUBLIC_DOWNLOAD_URL` antes do `download-manifest.json`):

1. `.env.production` no repositório — atualizado para 0.5.1;
2. **`.env.local` no Acer** (não versionado, vence o `.env.production`) — este
   era o que realmente prendia a página na 0.5.0.

As cinco linhas `NEXT_PUBLIC_DOWNLOAD_*` foram comentadas nos **dois** lugares
(no Acer, com backup em `.env.local.bak-*`; e no `.env.production` do repo),
deixando só o `_MANIFEST_URL`. Agora o site lê a versão do manifesto da release.

**Mas a página é estática:** o manifesto é buscado no *build*, não a cada
visita. Toda release nova ainda exige reconstruir o site no Acer:

```bash
ssh acer@100.102.202.63
cd ~/Documentos/Mapas_Facil && git pull
cd Fase_2_Site/web && pnpm build && systemctl --user restart mapas-facil-site
```

O que mudou é que já não é preciso *editar* nada — só reconstruir.
